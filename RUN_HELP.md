# RUN_HELP

How to build and run **Flyte**. Two independent parts:

1. **Frontend** — the React Native / Expo app (`src/`, `android/`) → runs on an Android emulator or device, driven from Android Studio.
2. **Server** — the C++ backend proxy (`server/`) → runs in Docker locally (no live deployment currently).

The UI currently uses mock data (`src/data/flights.ts`); it is **not** wired to the server yet, so you do not need the server running to run the app.

## 1.5 Generate / refresh the native `android/` project

`android/` and `ios/` are **git-ignored** and are generated from `app.json` + config plugins.

- **`android/` already exists** → skip this step.
- **`android/` is missing**, or you changed `app.json` / added a native dependency:
  ```bash
  npx expo prebuild            # regenerate android/ (keeps existing where possible)
  # or:  npx expo prebuild --clean   # nuke and regenerate from scratch
  ```
  **After any `prebuild`, recreate `android/local.properties`** (next step).

```properties
sdk.dir=C:\\Users\\bdhol\\AppData\\Local\\Android\\Sdk
```

(Double backslashes, or use forward slashes.) You must recreate this every time `android/` is regenerated by `expo prebuild`.

## 1.7 Build & run — Android Studio (GUI)

## 1.9 Everyday development loop

- Keep `npx expo start` running.
- Edit files under `src/` → press **`r`** in the Metro terminal (or `Ctrl+M` in the emulator → Reload).
- **No Gradle rebuild** is needed unless you add/remove a **native** dependency or change `app.json`. In that case: `npx expo prebuild`, recreate `local.properties`, then rebuild.

## 1.10 Troubleshooting (everything that has actually gone wrong here)

| Symptom | Cause & fix |
|---|---|
| `SDK location not found … local.properties` | `android/local.properties` missing → recreate it (1.6). |
| `Unsupported class file major version 69` | Gradle running on JDK 25 → point it at JDK 21 (1.3). |
| `expo run:android` complains **JAVA_HOME is not set** | Set `JAVA_HOME` for the shell: `set JAVA_HOME=C:\Users\bdhol\.jdks\jdk-21.0.12.1+1` (or `setx` permanently). |
| Metro: `Cannot find module 'react-native-worklets/plugin'` | `nativewind` drifted to 4.2.x (assumes Reanimated 4). Pin `"nativewind": "4.1.23"` exactly, `npm install`, restart Metro with `npx expo start -c`. |
| Redbox: `Cannot find native module 'ExpoAsset'` (or `ExpoFont`, etc.) | `expo-*` sub-packages got nested under `node_modules/expo/node_modules/` (circular peer dep) so Expo autolinking missed their native code. Fix: `npx expo install expo-asset expo-constants expo-font expo-file-system expo-keep-awake` (adds them as top-level deps), then `rm -rf android/app/build/generated` and rebuild so the autolinking package list regenerates. Verify with `npx expo-modules-autolinking search -p android` — it should list all the `expo-*` modules, not just `expo` + `expo-modules-core`. |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / "app must be uninstalled" | Old copy signed with a different debug keystore. `adb uninstall com.flyte.app`, or accept the Studio dialog, or uninstall it on the emulator. `expo prebuild --clean` regenerates the debug keystore, so this recurs once after each clean prebuild. |
| Emulator shows as "running" but there's **no window** / frozen home screen / clicks do nothing | Zombie QEMU process. `taskkill /F /T /IM qemu-system-x86_64.exe` (also `/IM adb.exe /IM crashpad_handler.exe`), then **Device Manager → Pixel_10_Pro → ⋮ → Cold Boot Now**. If still frozen: **⋮ → Wipe Data** (also clears the old installed app), and in the AVD's advanced settings set **Boot option = Cold boot** and try **Graphics = Software**. |
| Pressing `r` in Metro → *"No apps connected … failed"* | The app launched before Metro was up, or nothing is running. Ensure `npx expo start` is up, run `adb -s emulator-5554 reverse tcp:8081 tcp:8081`, then **fully relaunch** the app (tap its icon) so it reconnects on startup. |
| Metro: `Port 8081 is being used by another process` | A stale Metro is still bound. Find it: `netstat -ano | findstr :8081`, then `taskkill /F /T /PID <pid>`. Restart Metro. |
| `adb` hangs from a terminal | Usually a port clash with Android Studio's own adb server. `adb kill-server && adb start-server`, or just use the emulator UI / Studio dialogs instead. |

# Part 2 — Server: build & run

## 2.1 What it is

`server/` is a small **C++17** HTTP proxy:

- **cpp-httplib** server, one route: `GET /flights/:flightNumber`
- Calls the **AeroDataBox** API (RapidAPI) and maps the response to `models::FlightData` JSON
- Returns `404` with a JSON body when the flight isn't found
- Telemetry is `null` and events are `[]` for now (later phases)
- Dependencies via **Conan**: `cpp-httplib`, `nlohmann_json`, `libcurl`
- Built inside **Docker** (multi-stage: `debian:bookworm` build → `debian:bookworm-slim` runtime)
- Runs locally only for now — no live deployment

Port comes from `PORT` (default `8080`); it listens on `0.0.0.0`.

## 2.2 Prerequisites

| Tool | For |
|------|-----|
| **Docker Desktop** | local run (the normal path) |
| `server/.env` with a real `AERODATABOX_KEY` | required — the server throws on startup if missing |
| Python 3 + Conan + CMake + a C++ compiler | only if building **without** Docker (2.6) |

### `server/.env`

Already present on this machine. If you need to recreate it, copy the template and fill in your RapidAPI key:

```bash
cd D:\Dev\Flyte\server
copy .env.example .env
```

```properties
PORT=8080
AERODATABOX_KEY=your_rapidapi_key_here
```

## 2.3 Run locally with Docker Compose (normal path)

```bash
cd D:\Dev\Flyte\server
docker compose up --build
```

- Builds the `build` stage, mounts `./src` and a `build-cache` volume, runs `cmake --build` then the binary.
- Serves on **http://localhost:8080**.

Test it:

```bash
curl http://localhost:8080/flights/AS2223
```

You should get a JSON `FlightData` object (correct duration / delay / progress / `HH:mm` times; `telemetry` null, `events` `[]`). An unknown flight returns `404` with a JSON body.

Stop with `Ctrl+C`.

## 2.4 Gotcha: stale `build-cache` volume

The named `build-cache` volume populates from the image **once**. After that, every `up` mounts the same stale `/app/build`, so **dependency or config changes are silently ignored** — a fix that should work keeps failing identically. When you change `conanfile.py`, `CMakeLists.txt`, or the `Dockerfile`:

```bash
cd D:\Dev\Flyte\server
docker compose down -v          # -v drops the build-cache volume
docker compose up --build
```

## 2.5 Build the production image directly (optional)

This exercises the **runtime** stage that actually ships (slim image, no build tools) — `docker compose` runs the fatter `build` stage, so the two can diverge (a missing `ca-certificates` in runtime once broke TLS to AeroDataBox only in production).

```bash
cd D:\Dev\Flyte\server
docker build -t flyte-server .
docker run --rm -p 8080:8080 --env-file .env flyte-server
curl http://localhost:8080/flights/AS2223
```

## 2.6 Native build without Docker (optional, advanced)

Needs Conan, CMake, and a C++17 compiler on the host.

```bash
cd D:\Dev\Flyte\server
conan profile detect --force
conan install . --build=missing -s build_type=Release
cmake -S . -B build/Release ^
  -DCMAKE_TOOLCHAIN_FILE=build/Release/generators/conan_toolchain.cmake ^
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/Release
```

Run it (set env vars for your shell; the binary reads `PORT` and `AERODATABOX_KEY`):

```bash
# bash
PORT=8080 AERODATABOX_KEY=xxxxx ./build/Release/flyte_server
```
```cmd
:: cmd
set PORT=8080
set AERODATABOX_KEY=xxxxx
build\Release\flyte_server.exe
```

## 2.7 API reference

| Method | Path | Result |
|---|---|---|
| `GET` | `/flights/:flightNumber` | `200` → `FlightData` JSON (schedule fields populated; `telemetry: null`, `events: []`). `404` → JSON error body when not found. A RapidAPI `429` rate-limit is currently also surfaced as `404`. |

Data model: `server/src/models/flight_data.h` (C++ structs + JSON) and `src/types/flight.ts` (Zod), kept field-matched.
