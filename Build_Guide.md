# Flyte — Build Guide

Portable build & run instructions for a fresh checkout of this source archive.

The project has two independent parts:

1. **Frontend** — a React Native / Expo app (`src/`) that runs on an Android emulator or device.
2. **Server** — a C++17 HTTP proxy (`server/`) that runs in Docker (no live deployment currently).

The UI currently uses mock data (`src/data/flights.ts`) and is **not** wired to the server, so you do **not** need the server running to run the app.

> This archive omits regenerated / machine-specific content: `node_modules/`, `android/`, `.expo/`,
> `server/build/`, and `server/.env`. All of it is recreated by the steps below.

---

## Part 1 — Frontend

### 1.1 Stack

- Expo SDK 53 / React Native 0.79.6 / React 19
- NativeWind v4 (`4.1.23`, pinned — see 1.6), `react-native-svg`, `lucide-react-native`,
  `@react-native-async-storage/async-storage`, `react-native-reanimated`
- New Architecture enabled (`newArchEnabled: true` in `app.json`)

### 1.2 Prerequisites (one-time)

| Tool | Notes |
|------|-------|
| **Node.js 20 or 22** + npm | `node -v` |
| **Android Studio** | Includes the emulator and SDK Manager |
| **Android SDK components** | `platforms;android-35`, `build-tools;35.0.0`, `ndk;27.1.12297006`, `platform-tools`. Install the NDK explicitly from the SDK Manager. |
| **JDK 17 or 21** | **Not JDK 25.** Gradle 8.13 cannot run on JDK 25 (`Unsupported class file major version 69`). Android Studio's bundled JBR may be 25 — install a separate Temurin 17 or 21. |
| **An emulator (AVD)** | Create one in Android Studio → Device Manager (e.g. Pixel 7 / Pixel 10 Pro, API 35). |

### 1.3 Environment setup

Set these for your OS (replace paths with yours):

```bash
# macOS / Linux (~/.zshrc or ~/.bashrc)
export JAVA_HOME="/path/to/jdk-21"
export ANDROID_HOME="$HOME/Library/Android/sdk"      # or ~/Android/Sdk on Linux
```

```cmd
:: Windows (run once in cmd, then reopen terminals + restart Android Studio)
setx JAVA_HOME "C:\path\to\jdk-21"
setx ANDROID_HOME "%LOCALAPPDATA%\Android\Sdk"
```

Make command-line Gradle use JDK 21 regardless of the system default — create/edit
`~/.gradle/gradle.properties`:

```properties
org.gradle.java.home=/path/to/jdk-21
```

For **Android Studio GUI builds**, also set:
**Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → 21**.

### 1.4 Install JS dependencies

```bash
cd Flyte
npm install
```

> **Do not "clean up" these `package.json` entries — they are load-bearing:**
> - `"nativewind": "4.1.23"` — pinned with **no caret**. 4.2.x assumes Reanimated 4 and breaks
>   Metro with `Cannot find module 'react-native-worklets/plugin'`.
> - `expo-asset`, `expo-constants`, `expo-font`, `expo-file-system`, `expo-keep-awake` — listed as
>   explicit top-level deps on purpose. Without this they nest under `node_modules/expo/node_modules/`
>   and Expo autolinking misses their native code (redbox: `Cannot find native module 'ExpoAsset'`).

### 1.5 Generate the native `android/` project

`android/` and `ios/` are not in this archive; they are generated from `app.json` + config plugins.

```bash
cd Flyte
npx expo prebuild            # generate android/ (and ios/ on macOS)
# or: npx expo prebuild --clean   # nuke and regenerate from scratch
```

### 1.6 Create `android/local.properties` (required, git-ignored)

Command-line Gradle and `expo run:android` need this file. Create `Flyte/android/local.properties`
with one line pointing at your SDK:

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

On Windows use double backslashes or forward slashes:
`sdk.dir=C:\\Users\\you\\AppData\\Local\\Android\\Sdk`

Recreate this file every time `android/` is regenerated by `expo prebuild`.

### 1.7 Build & run

**Command line (simplest).** Boot the emulator first, then:

```bash
cd Flyte
npx expo run:android
```

This runs the Gradle build, installs the app, sets up `adb reverse tcp:8081`, launches it, and
starts Metro. First build is cold (~7 min); later runs are fast. First JS bundle takes ~60 s
(~2700 modules) — you'll see "Bundling …%" on a dark screen, then the Home screen.

**Android Studio (GUI).**

1. Open the **`android/` folder** in Android Studio — not the repo root.
2. Let the first Gradle sync finish (it fills in `local.properties` if you skipped 1.6).
3. Confirm **Gradle JDK = 21**.
4. In a separate terminal: `cd Flyte && npx expo start` — leave it running.
5. Start the emulator and wait for its home screen.
6. Pick that device in Android Studio and click **▶ Run**.

**Expected result:** FLYTE logo, "Track your flight.", a search box with
`AA2847 / DL1089 / UA421 / BA178` chips, and a RECENT row `AA 2847 · On Time · JFK → LAX`.

### 1.8 Development loop

- Keep `npx expo start` running.
- Edit files under `src/` → press **`r`** in the Metro terminal (or shake / `Ctrl+M` in the
  emulator → Reload).
- **No Gradle rebuild** is needed unless you add/remove a **native** dependency or change `app.json`.
  Then: `npx expo prebuild`, recreate `local.properties` (1.6), rebuild.

### 1.9 Troubleshooting

| Symptom | Cause & fix |
|---|---|
| `SDK location not found … local.properties` | Create `android/local.properties` (1.6). |
| `Unsupported class file major version 69` | Gradle is on JDK 25 → point it at JDK 21 (1.3). |
| `expo run:android`: **JAVA_HOME is not set** | `export JAVA_HOME=/path/to/jdk-21` (or `set` / `setx` on Windows) for that shell. |
| Metro: `Cannot find module 'react-native-worklets/plugin'` | `nativewind` drifted to 4.2.x → pin `"nativewind": "4.1.23"` exactly, `npm install`, restart with `npx expo start -c`. |
| Redbox: `Cannot find native module 'ExpoAsset'` (or `ExpoFont`, …) | `npx expo install expo-asset expo-constants expo-font expo-file-system expo-keep-awake`, then delete `android/app/build/generated` and rebuild. Verify with `npx expo-modules-autolinking search -p android`. |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / "app must be uninstalled" | Old copy signed with a different debug keystore → `adb uninstall com.flyte.app` and reinstall. Recurs once after each `prebuild --clean`. |
| Emulator "running" but no window / frozen | Kill the QEMU process, then Device Manager → your AVD → **Cold Boot Now**. If still stuck: **Wipe Data**. |
| Pressing `r` in Metro → "No apps connected" | App launched before Metro was up. Ensure `npx expo start` is running, `adb reverse tcp:8081 tcp:8081`, then fully relaunch the app. |
| Metro: `Port 8081 is being used by another process` | Stale Metro still bound — kill the process holding `:8081`, restart. |

### 1.10 Useful commands

```bash
adb devices
adb -s emulator-5554 reverse tcp:8081 tcp:8081
adb -s emulator-5554 shell am force-stop com.flyte.app
adb -s emulator-5554 logcat -d | grep -Ei "ReactNativeJS|FATAL"
cd android && ./gradlew :app:assembleDebug        # native build only
# Debug APK: android/app/build/outputs/apk/debug/app-debug.apk
```

## Part 2 — Server

### 2.1 What it is

`server/` is a small **C++17** HTTP proxy:

- **cpp-httplib** server, one route: `GET /flights/:flightNumber`
- Calls the **AeroDataBox** API (via RapidAPI) and maps the response to `models::FlightData` JSON
- Returns `404` with a JSON body when the flight isn't found (a RapidAPI `429` is currently also
  surfaced as `404`)
- `telemetry` is `null` and `events` is `[]` for now (later phases)
- Dependencies via **Conan**: `cpp-httplib`, `nlohmann_json`, `libcurl`
- Built inside **Docker** (multi-stage: `debian:bookworm` build → `debian:bookworm-slim` runtime)
- Runs locally only for now — no live deployment

Port comes from `PORT` (default `8080`); it listens on `0.0.0.0`.

### 2.2 Prerequisites

| Tool | For |
|------|-----|
| **Docker Desktop** | local run (the normal path) |
| `server/.env` with a real `AERODATABOX_KEY` | required — the server throws on startup if missing |
| Python 3 + Conan + CMake + a C++17 compiler | only for a native build without Docker (2.6) |

### 2.3 Create `server/.env`

```bash
cd Flyte/server
cp .env.example .env        # copy .env.example .env  on Windows
```

Then edit `.env`:

```properties
PORT=8080
AERODATABOX_KEY=your_rapidapi_key_here
```

### 2.4 Run locally with Docker Compose (normal path)

```bash
cd Flyte/server
docker compose up --build
```

Serves on **http://localhost:8080**. Test it:

```bash
curl http://localhost:8080/flights/AS2223
```

You should get a JSON `FlightData` object (correct duration / delay / progress / `HH:mm` times;
`telemetry` null, `events` `[]`). An unknown flight returns `404` with a JSON body. Stop with `Ctrl+C`.

### 2.5 Gotcha: stale `build-cache` volume

The named `build-cache` volume populates from the image **once**. After that every `up` mounts the
same stale `/app/build`, so dependency/config changes are silently ignored. When you change
`conanfile.py`, `CMakeLists.txt`, or the `Dockerfile`:

```bash
cd Flyte/server
docker compose down -v          # -v drops the build-cache volume
docker compose up --build
```

### 2.6 Build the production image directly (optional)

`docker compose` runs the fatter `build` stage; this exercises the slim **runtime** stage that
actually ships (the two can diverge):

```bash
cd Flyte/server
docker build -t flyte-server .
docker run --rm -p 8080:8080 --env-file .env flyte-server
curl http://localhost:8080/flights/AS2223
```

### 2.7 Native build without Docker (optional, advanced)

Needs Conan, CMake, and a C++17 compiler on the host.

```bash
cd Flyte/server
conan profile detect --force
conan install . --build=missing -s build_type=Release
cmake -S . -B build/Release \
  -DCMAKE_TOOLCHAIN_FILE=build/Release/generators/conan_toolchain.cmake \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/Release
```

Run it (the binary reads `PORT` and `AERODATABOX_KEY` from the environment):

```bash
PORT=8080 AERODATABOX_KEY=xxxxx ./build/Release/flyte_server
```

### 2.8 API reference

| Method | Path | Result |
|---|---|---|
| `GET` | `/flights/:flightNumber` | `200` → `FlightData` JSON (schedule fields populated; `telemetry: null`, `events: []`). `404` → JSON error body when not found. |

Data model: `server/src/models/flight_data.h` (C++ structs + JSON) and `src/types/flight.ts` (Zod),
kept field-matched.
